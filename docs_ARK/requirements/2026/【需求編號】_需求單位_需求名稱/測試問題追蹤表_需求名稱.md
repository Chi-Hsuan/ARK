# 測試問題追蹤表

記錄測試期間發現的問題，並由 SA 判定影響層面，決定需連動更新哪些文件，避免文件與程式不一致。

## 欄位定義

| 欄位 | 說明 |
| --- | --- |
| 影響層面 | 由 SA 判定，見下方定義 |
| 應更新文件 | 依影響層面連動的文件，可複選；純程式修正填「無」 |
| 文件更新狀態 | 待更新 / 已更新 / 不需更新（填「不需更新」須於備註說明原因） |
| 狀態 | 待確認 / 修正中 / 待驗證 / 已結案 / 不修正 |

### 影響層面定義

| 影響層面 | 說明 | 應更新文件 |
| --- | --- | --- |
| 需求面 | 原始需求描述有誤或漏列，需求範圍本身要調整 | 需求書 → 異動影響評估書 → 系統規格 |
| 規格面 | 需求正確，但異動評估或系統規格寫錯、寫漏 | 異動影響評估書 / 系統規格 |
| 程式面 | 需求與規格皆正確，單純實作與規格不符 | 無 |

> 需求面的異動會往下游擴散，需回頭確認異動影響評估書與系統規格是否同步調整。

## 驗收檢核

> 開發完成、進入測試**之前**的閘門。逐條確認實作是否達成驗收標準，未通過不進測試。
> `AC-` 來自需求書第五節，`AC-T` 來自異動影響評估書（上游影響、資料庫異動、決策事項）。

| AC 編號 | 驗收條件 | 來源 | 驗證方式 | 對應單元測試 | 檢核結果 | 檢核人 / 日期 |
| --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |

**檢核結果**：未檢核 / 通過 / 未通過 / 不適用（填「不適用」須說明原因）

未通過時分兩種處理：實作沒做到就回去改；規格或需求本身說不清楚，回報 SA 處理，不要自行解讀後實作。
