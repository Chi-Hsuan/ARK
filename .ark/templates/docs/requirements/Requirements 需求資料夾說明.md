# Requirements 需求資料夾說明

本文件說明需求文件的存放結構與命名規則。所有需求以「一需求一資料夾」的方式管理，並依年度分層存放。

## 檔案架構

```
requirements/
├── Requirements 需求資料夾說明.md            # 本檔案，說明需求資料夾結構與命名規則
├── requirement_index.md                     # 需求總管，所有需求的單一入口索引
└── {年度}/                                   # 依需求開立年度分資料夾 (ex. 2026)
    └── 【需求編號】_需求單位_需求名稱/         # 單一需求資料夾
        ├── 需求書_需求名稱.md                 # PO 依需求單位提出之需求撰寫的需求說明文件
        ├── 異動影響評估書_需求名稱.md          # SA 撰寫的異動範圍與影響評估
        ├── 測試問題追蹤表_需求名稱.md          # SIT / UAT 問題追蹤，含影響層面判定與文件連動狀態
        ├── release_docs/                      # 上線文件存放區 (Checkmarx、SonarQube 掃描報告等)
        └── bu_reference/                      # 需求單位 (BU) 提供的重要參考文件
```

## 命名規則

### 需求資料夾

- 格式：`【需求編號】_需求單位_需求名稱`
- 範例：`【RF20260037】_存管部_約轉設定失效虛擬帳號移除`
- 需依需求開立的年度，放入對應的年度資料夾（ex. 2026）

### 需求文件

一律使用**半形底線** `_` 連接，`{需求名稱}` 需與所屬資料夾的需求名稱一致。

| 文件 | 命名格式 | 範例 |
| --- | --- | --- |
| 需求書 | `需求書_{需求名稱}.md` | 需求書_約轉設定失效虛擬帳號移除.md |
| 異動影響評估書 | `異動影響評估書_{需求名稱}.md` | 異動影響評估書_約轉設定失效虛擬帳號移除.md |
| 測試問題追蹤表 | `測試問題追蹤表_{需求名稱}.md` | 測試問題追蹤表_約轉設定失效虛擬帳號移除.md |

### 附件資料夾

| 資料夾 | 存放內容 | 檔名規則 |
| --- | --- | --- |
| `release_docs/` | 上線相關文件，如 Checkmarx、SonarQube 掃描報告 | 沿用原始檔名 |
| `bu_reference/` | 需求單位提供的重要參考文件 | 沿用原始檔名 |

## 新增需求流程

1. 先於 [requirement_index.md](requirement_index.md) 登錄一列
2. 依上述命名規則建立需求資料夾與文件
3. 需求上線後，將本次異動回寫至 [library/](../library/)，並於需求總管更新「知識庫同步」欄位
