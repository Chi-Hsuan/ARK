# Code 程式碼資料夾說明

本資料夾放**實際的程式碼**，讓文件與程式在同一個 workspace 底下，agent 讀規格與讀程式不必跨專案。

一個系統一個子資料夾，通常直接 `git clone` 進來。

```
{docs_root}/code/
├── README.md          # 本檔，會進版控
├── .gitignore         # 排除規則，會進版控
├── {系統A}/            # 各自帶 .git，不進文件 repo 的版控
└── {系統B}/
```

## 版控規則

**本資料夾的內容不納入 `{docs_root}` 所在 repo 的版控。**

原因是這裡的每個子資料夾都是**獨立的 git 倉庫**，有自己的分支、歷史與遠端。把它們一起提交到文件 repo 會變成巢狀 repo，兩邊的歷史互相干擾。

排除方式寫在本資料夾的 `.gitignore`：忽略所有內容，只保留 `README.md` 與 `.gitignore` 本身。因此**團隊其他人 clone 文件 repo 時只會拿到這份說明**，程式碼要自己依下表取得。

程式碼的版控（branch、commit、push）一律在各自的子資料夾內操作，與文件 repo 無關。

## 自行取得或新增

在本資料夾底下 clone：

```bash
cd {docs_root}/code
git clone <repo-url>
```

完成後把該倉庫補進上面的表格。

不使用 git 的程式碼（例如既有的壓縮檔、供應商交付的原始碼）也可以直接放進本資料夾，同樣不會進文件 repo 的版控，一樣在表格中登記一列並在說明欄註明來源。

## 程式碼放在別處時

不放這裡也可以。ARK 的技能要讀程式時，會先看 `.ark/config.yml` 的 `code_root`，沒設定才用本資料夾；在本資料夾找不到程式碼時會停下來問，答案會寫回 `code_root`，之後不再重問。

改用其他位置時，在上面的表格登記一列、說明欄註明實際路徑，讓看文件的人也知道去哪找。
