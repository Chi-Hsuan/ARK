# ARK 文件範本

`.ark/skills/` 底下的技能建立文件時，一律**複製本資料夾的範本**，不要自行生成結構。

| 範本 | 用途 | 由誰填寫 |
| --- | --- | --- |
| `需求書.md` | 需求說明 | Navigator（PO） |
| `異動影響評估書.md` | 異動範圍與影響評估 | Architect（SA） |
| `測試問題追蹤表.md` | 測試問題追蹤與文件連動 | Architect（SA），Builder 回報問題 |

## 使用方式

1. 完整複製範本檔到目標需求資料夾，檔名依 `{docs_root}` 底下說明文件的命名規則
2. 置換 `{需求名稱}`、`{docs_root}` 等佔位符
3. 填入已知資訊，**其餘保留原樣**

## 為什麼不要刪掉空欄位

範本裡的空白欄位與註解是刻意留下的：

- 空欄位代表「這件事還沒想」，刪掉之後就變成「這件事不存在」，兩者的後果差很多
- 引言（`>` 開頭）說明該欄位的填寫意圖與常見錯誤，是給填寫者看的，定版前不需要移除
- 標記 ★ 的欄位是流程的把關點，未確認不應進入下一階段

技能在建立文件時只做「複製 + 置換佔位符 + 填入已知資訊」，**不要因為某段看起來用不到就精簡掉**。要不要刪是填寫者的決定。

## 修改範本

範本改動會影響所有之後建立的文件，但**不會回溯**既有文件。若改動屬於流程層級（例如新增一個必填的把關欄位），應同步考慮是否要提高 `.ark/config.yml` 的 `ark_version`。
