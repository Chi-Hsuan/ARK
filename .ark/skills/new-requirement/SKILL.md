# 開立新需求

## 前置檢查

1. 讀 `.ark/config.yml`。不存在則告知使用者此專案尚未導入 ARK 並停止
2. 取得 `docs_root`
3. 讀 `{docs_root}/requirements/` 底下的說明文件，取得**當前專案實際的命名規則**——不要套用記憶中的格式，各專案可能不同

## 收集資訊

用互動式問題工具依序詢問，一次問一件：

| 欄位 | 說明 |
| --- | --- |
| 需求編號 | 若使用者尚未取得，可先留白，之後補 |
| 需求單位 | 提出需求的部門 |
| 需求聯絡人 | 提出需求的部門之聯絡人 |
| 需求聯絡人分機 | 提出需求的部門之聯絡人分機（選填） |
| 需求名稱 | 簡短可辨識，會用於資料夾與所有檔名 |
| 年度 | 預設當年度，可指定 |
| PO | |
| SA | 可先留白，之後補 |

需求名稱要提醒使用者：它會成為資料夾與三份文件的檔名，命名後再改要動很多地方，先想清楚。

## 建立

1. 依說明文件的格式建立需求資料夾於 `{docs_root}/requirements/{年度}/`，若尚無該年度資料夾，則先建立該年度資料夾
2. 建立附件資料夾（依說明文件，通常是 `release_docs/`、`bu_reference/`），並在每個資料夾放一個 `.gitkeep`——空資料夾不會進版控，團隊其他人 clone 後會看不到
3. 從 `.ark/templates/` **複製**三份範本到需求資料夾，檔名依說明文件的格式：

   | 範本 | 產生的文件 |
   | --- | --- |
   | `.ark/templates/需求書.md` | `需求書_{需求名稱}.md` |
   | `.ark/templates/異動影響評估書.md` | `異動影響評估書_{需求名稱}.md` |
   | `.ark/templates/測試問題追蹤表.md` | `測試問題追蹤表_{需求名稱}.md` |

   複製後只做三件事：置換 `{需求名稱}`、`{docs_root}` 等佔位符；填入已收集到的資訊（需求編號、提出單位、需求聯絡人、PO / SA）；其餘**保留原樣**。

   空欄位、引言、★ 標記都是刻意留下的，不要為了「看起來乾淨」而刪減或改寫結構，理由見 `.ark/templates/README.md`。範本不存在時停下來告知使用者，**不要自行生成文件結構**。
4. 在需求總管新增一列，欄位對齊既有表頭：
   - 狀態填說明文件定義的初始狀態
   - 知識庫同步填 `—`
   - **需求開立時間填今天日期**，格式沿用該表既有列的寫法。這欄是其他技能排序「最近開立的需求」的依據，不可留白

**建立前先確認資料夾是否已存在**。存在則停下來問使用者要不要沿用，不要覆寫。

## 完成後

回報建立了哪些檔案，並提醒下一步：需求書的內容需要與需求單位確認後補完，可以繼續用 Navigator 撰寫。

若需求編號當時留白，提醒使用者取得後要同時更新資料夾名稱與需求總管。
