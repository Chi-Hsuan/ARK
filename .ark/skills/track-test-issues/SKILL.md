# 測試問題追蹤

檢視與維護既有的測試問題。**新增問題請改用 `.ark/skills/log-test-issue/SKILL.md`。**

## 前置檢查

1. 讀 `.ark/config.yml`，取得 `docs_root`
2. 讀 `.ark/workflow.md` 的「影響層面判定」章節

## 步驟一：選擇範圍

用互動式選單提供兩種：

| 範圍 | 說明 |
| --- | --- |
| 單一需求 | 依開立時間列出最近 10 筆供選擇，並附輸入欄位可輸入需求編號或名稱 |
| 全部進行中的需求 | 讀需求總管，涵蓋所有尚未上線的需求，跨需求總覽 |

選定的需求沒有測試問題追蹤表時告知使用者，並詢問是否要登錄第一筆問題（轉 `log-test-issue`）。

## 步驟二：呈現

依**環境**分區，區塊內依狀態排序（未結案在前）。預設**收合已結案與不修正**的項目，只顯示數量，使用者要求時再展開。

> `## 欄位定義` 與 `## 驗收檢核` 是保留區塊，**不是測試環境**，不要當成環境呈現，裡面的 `AC-` 也不是測試問題。驗收檢核由 `.ark/skills/check-acceptance/SKILL.md` 負責。

```
🧪 測試問題追蹤　·　RF20260037 約轉設定失效虛擬帳號移除
未結案 4　·　文件待更新 2　·　已結案 6

## SIT　(3 未結案 / 5 總數)

- 🔧 **SIT-03**　查詢結果未過濾已失效帳號
  規格面　·　SA 陳大同
  📄 待更新：異動影響評估書 / 系統規格

- 👀 **SIT-05**　匯出檔編碼錯誤
  程式面　·　PG

## UT　(1 未結案 / 3 總數)

...

## UAT　(0 未結案 / 0 總數)

（尚無問題）
```

狀態圖示：

| 圖示 | 狀態 |
| --- | --- |
| 🆕 | 待確認 |
| 🔧 | 修正中 |
| 👀 | 待驗證 |
| ✅ | 已結案 |
| ⛔ | 不修正 |

狀態值不在該表「欄位定義」章節列出的範圍內時，照原文顯示並加上 `❓`，提醒使用者該值不在定義中。

跨需求總覽時，改以需求為第一層分區，環境為第二層，並在最上方給各需求的未結案數摘要。

## 步驟三：標記異常

呈現時一併標出下列狀況：

| 標記 | 條件 | 為什麼要抓 |
| --- | --- | --- |
| 🔴 | **狀態為已結案，但文件更新狀態仍是「待更新」** | 問題修完了、文件卻沒改，這是文件與程式脫鉤最常見的入口 |
| 📄 | 未結案且文件更新狀態為「待更新」 | 待辦提醒 |
| ⚠️ | 影響層面或負責人留白 | 沒判定就無從追蹤該改哪份文件 |
| ⛔❓ | 標為「不修正」但備註留白 | 不修正的理由必須留下，否則事後無法查核 |

🔴 是本技能最重要的檢查，呈現時**放在最前面**單獨列出，不要混在各環境區塊裡。

## 步驟四：更新（使用者要求時）

選定一筆問題後，可更新下列欄位：

| 欄位 | 說明 |
| --- | --- |
| 狀態 | 依該表欄位定義的可用值 |
| 影響層面 | 改判會連動其他欄位，見下方 |
| 文件更新狀態 | 待更新 / 已更新 / 不需更新 |
| 負責人 | |
| 備註 | |

### 改判影響層面時

**必須同步重新推導**這三欄，不能只改影響層面：

| 影響層面 | 應更新文件 | 文件更新狀態 | 主責角色 |
| --- | --- | --- | --- |
| 需求面 | 需求書 → 異動影響評估書 → 系統規格 | 待更新 | PO 與 SA 並列 |
| 規格面 | 異動影響評估書 / 系統規格 | 待更新 | SA |
| 程式面 | 無 | 不需更新 | PG |

人名取自需求總管的 PO / SA 欄，抓不到就只寫角色代號。

由程式面改判為需求面或規格面時，特別提醒使用者：原本不用改的文件現在要改了。

### 結案前的檢查

狀態要改為「已結案」而文件更新狀態仍是「待更新」時，**先問使用者**：

- 文件其實已經改好了 → 一併把文件更新狀態改為「已更新」
- 文件還沒改 → 提醒先處理文件，或確認要在文件未更新的狀態下結案

使用者確認後照做，但不要靜默結案。

### 標為「不修正」時

要求填寫備註說明原因。沒有原因的「不修正」與漏掉沒有分別。

## 完成後

1. 回報實際更新的每一處
2. 仍有 🔴 項目時再次列出
3. 需求總管中該需求的狀態若與實際情形不符（例如問題全部結案但狀態還停在「測試中」），提醒使用者是否要更新

## 規則

- 只動測試問題追蹤表。需求總管、需求書、規格文件都不在本技能的修改範圍內，需要改時提醒使用者切換角色
- 表格欄位以該檔案實際的表頭為準，不要照本文的順序硬填
- 所有內容取自檔案，不要推測未填寫的欄位
